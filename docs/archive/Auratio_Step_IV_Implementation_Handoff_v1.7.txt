CURRENT KNOWN DEFECTS

V-01 — REOPENED EVALUATION ROUTE / VERSIONING SAFETY

Current risk:
`/volunteer/evaluation/:submissionId/reopened`

The current page can use fallback values if no legitimate prior submitted version exists.

`reopenEvaluation()` can potentially create active correction work for an invalid or unsupported ID.

`getPreservedLockedSubmission()` defaults to version 1, so repeated reopen cycles may not reliably advance from the latest legitimate submitted version.

Required:
- Reopened Evaluation requires a real locked/completed evaluator submission.
- invalid/unsubmitted ID -> safe redirect.
- no fabricated Business Pitch / 85 fallback.
- reopening must use the latest valid locked submission.
- version N re-review -> version N+1.
- every prior locked version remains immutable.

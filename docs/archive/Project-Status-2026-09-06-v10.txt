CURRENT KNOWN DEFECTS — MUST BE RESOLVED TOMORROW

Two Volunteer portal defect groups are currently known.

KNOWN DEFECT V-01 — Reopened Evaluation route can fabricate / mishandle unsupported or repeated reopen state.

Current concern:
- `/volunteer/evaluation/:submissionId/reopened` does not yet sufficiently require a legitimate submitted/locked prior version.
- invalid IDs can potentially enter a fabricated correction workflow.
- reopen logic may fall back to default Business Pitch data when no legitimate prior submission exists.
- version lookup defaults to version 1, creating risk that repeated reopen cycles rebuild from an old locked version instead of the latest valid submitted version.

Required future correction:
- invalid/unsubmitted IDs must not enter Reopened Evaluation.
- formal reopen must require a real completed/locked prior evaluator version.
- repeated re-review must always advance from the latest valid locked version.
- prior locked versions must remain immutable and reconstructible.

KNOWN DEFECT V-02 — Generic Completed-detail route is hard-coded to SUB-8821.

Current route:
`/volunteer/completed/:submissionId`

Current component:
VolunteerCompletedPendingModerationPage

Current problem:
- page content is hard-coded to SUB-8821
- score is hard-coded to 85 / 100
- if another submission such as SUB-8814 is actually submitted and its history row opens `/volunteer/completed/sub-8814`, the page can display SUB-8821 data

Required future correction:
- Completed-detail rendering must resolve the exact selected submission.
- route ID, displayed ID, track, score, and publication state must agree.
- unknown IDs must fail/redirect safely.
- no entity A may render entity B.

These defects are known and Step IV therefore cannot be declared Zero Known Defects yet.
